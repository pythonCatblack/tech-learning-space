16.2 深度学习模型优化

16.2.1 模型量化

模型量化是嵌入式部署最重要的优化手段——将FP32模型转换为INT8或FP16，显著降低计算量和内存占用。

📉

FP32 → FP16

精度损失小，通常< 1%，推理加速约2倍。TensorRT和ONNX Runtime均支持。

📊

FP32 → INT8

精度损失稍大，需要校准数据集，加速可达4-8倍。主流目标检测模型均有成熟量化方案。

16.2.2 TensorRT加速

TensorRT是NVIDIA的推理优化框架——它通过算子融合、内核自动调优、内存优化等手段，可以将深度学习推理速度提升5-10倍。

🛠️ 动手实践

TensorRT INT8量化完整流程（YOLOv8）

# ① 导出ONNX模型（PyTorch）
python export.py --weights yolov8n.pt --include onnx

# ② 使用trtexec进行INT8量化
trtexec \
  --onnx=yolov8n.onnx \
  --int8 \
  --calib=./calib_dataset/ \
  --saveEngine=yolov8n_int8.engine \
  --verbose

# ③ 在Jetson Orin上运行
./yolov8n_int8.engine

# 性能对比
# FP32: 25 FPS @ Orin Nano
# FP16: 55 FPS @ Orin Nano  
# INT8: 120 FPS @ Orin Nano  ← 实际可满足实时避障要求

16.3 实时化与功耗优化

16.3.1 ROS2实时化

ROS2的实时性比ROS1大幅提升——支持确定性DDS通信、节点级别的实时线程调度。对于飞控链路（感知→决策→控制），实时性是硬性要求。

⚡

动态电压频率调节 (DVFS)

根据计算负载动态调整CPU/GPU频率和电压。轻载时降频省电，满载时超频保证性能。

🧊

模型层剪枝

去除冗余神经元和连接，减少计算量。常用方法：结构性剪枝（去除整个通道）。

🎯

Jetson电源模式

Orin Nano支持15W/25W/40W三档功率模式。在无人机上通常选MAXN 40W模式以保证算力。

16.3.2 功耗测试实战

🔑 无人机感知系统的功耗预算

以DJI Matrice 350 RTK为例：
• 起飞重量：约2.5kg

16.4 工程实践清单

1

算法选型

2

3

算子融合

使用TensorRT或供应商SDK将多个小算子融合为一个，减少内存访问。

4

功耗测试

在实际飞行中测量感知系统的功耗，确保不超过飞行预算。

⚠️
常见陷阱① - INT8量化精度崩溃：某些模型（如小模型YOLOv8n）对INT8量化非常敏感——精度下降超过10%。解决：先用FP16验证精度，INT8仅在精度损失< 2%时才可接受。

常见陷阱② - 忽视散热导致降频：Orin Nano在25°C环境温度+密闭无人机机体内时，芯片温度可能超过85°C，触发热保护自动降频至15W模式——算力从40TOPS骤降至15TOPS，导致LIO-SAM丢帧。必须加散热片+主动风扇。

常见陷阱③ - CUDA内存泄漏：在长时间飞行中（如1小时+），点云处理如果不及时释放GPU内存，会导致显存碎片化，最终OOM崩溃。每帧处理完后必须显式调用 cudaFree。

课后测验

第16章选择题

1. 模型量化（FP32→INT8）中，量化误差的统计特性对推理精度有显著影响。请分析：为什么某些网络架构（如ResNet）对INT8量化更鲁棒，而另一些网络（如MobileNet）可能严重降质？这个现象与网络权重的激活分布的什么统计特性相关？
A. 量化精度损失与激活分布的动态范围和均匀性相关：ResNet的激活分布相对均匀，量化误差近似高斯分布，均值接近零；MobileNet等轻量网络使用深度可分离卷积，激活分布往往呈双峰或长尾分布，量化误差有偏，导致精度严重下降；此外，通道级（channel-wise）量化比层級量化精度更高，因为可以更好地适应不同通道激活分布的差异
B. 所有网络量化效果相同
C. 网络规模越大越难量化
D. 量化与激活分布无关

2. 在Jetson Orin平台上，TensorRT的INT8推理需要校准数据集（Calibration Dataset）。请分析：校准数据集的作用是什么？为什么校准数据集的分布必须与实际推理数据分布一致？如果不一致会产生什么精度问题？
A. INT8量化需要将FP32权重和激活映射到INT8的256个离散值；校准过程通过统计FP32激活的分布来确定最优的量化边界（阈值）；如果校准数据与实际数据分布不一致，量化边界会偏移，导致实际推理时大量激活值被截断或聚集在少数量化级别上，精度严重下降；好的校准数据集应覆盖实际场景的各种输入情况
B. 校准数据集不影响精度
C. 校准可以离线进行
D. 量化不需要边界

3. 在嵌入式平台进行模型部署时，内存带宽（Memory Bandwidth）往往是比计算吞吐量（TOPS）更受限的瓶颈。请分析：为什么在深度学习推理中，内存访问代价可能远大于计算代价？这与模型的什么特性相关？如何通过算子融合（Operator Fusion）来缓解内存带宽瓶颈？
A. 现代GPU/AI芯片的计算吞吐量远高于内存带宽（TOPS vs TB/s）；每次计算都需要从内存读取权重和写入激活值，内存访问能耗是计算的数百倍；算子融合通过将多个独立操作合并为单个Kernel，减少中间结果的内存读写（如将Conv+BN+ReLU融合为单一算子），显著降低内存访问次数和带宽需求
B. 计算代价总是大于内存代价
C. 算子融合会增加内存访问
D. 内存带宽不影响推理速度

4. 在无人机嵌入式部署中，功耗预算直接影响飞行时间。假设感知系统（ Jetson Orin + Lidar）额定功耗为20W，电池容量为150Wh，请计算：仅感知系统满载运行，无人机最多能飞行多长时间？如果通过DVFS将Orin降至10W功耗模式，续航时间能提升多少百分比？
A. 满载20W时续航 = 150Wh / 20W = 7.5小时（理论值，实际会因电机等其他功耗略短）；降至10W后续航 = 150Wh / 10W = 15小时；提升百分比 = (15-7.5)/7.5 × 100% = 100%；即功耗减半，续航翻倍；但实际中需要考虑感知性能是否满足任务要求
B. 续航与功耗无关
C. 功耗降低一倍续航提升不到一倍
D. 20W感知系统不影响续航

5. 在CUDA编程中，GPU内存泄漏（Memory Leak）和内存碎片化（Memory Fragmentation）是长时间运行无人机感知系统可能面临的问题。请分析：这两种问题的成因有什么区别？为什么内存碎片化比内存泄漏更难调试？在实际工程中，如何通过内存池（Memory Pool）设计来预防这些问题？
A. 内存泄漏：allocated但未释放的显存持续积累，最终导致OOM；碎片化：频繁分配/释放导致显存中出现大量不连续的小块，即使总显存充足也无法分配大块连续内存；碎片化更难调试因为症状间歇性出现；内存池通过预分配固定大小块（固定size pool）或多种规格块（fixed size class pool），减少动态分配释放次数，是防止碎片化的有效方法
B. 泄漏和碎片化是同一问题
C. 内存池会增加泄漏风险
D. 碎片化问题可以忽略
