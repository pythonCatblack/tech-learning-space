一架无人机不是传感器的简单堆叠。飞控架构决定了传感器如何接入系统，机体结构限制了传感器安装位置和视野（FOV），有效载荷决定了总算力预算。理解这些物理约束，才能理解为什么大疆用双目视觉而不是激光雷达做消费级避障——不是因为双目"更好"，而是因为它更轻、更便宜、更适合消费级产品的约束。

2.1 无人机平台类型与感知需求

不同类型的无人机平台，对感知系统的需求差异巨大。选型之前，必须先理解平台特性。

2.1.1 多旋翼（Multirotor）——最灵活的空中机器人

多旋翼（四旋翼/六旋翼/八旋翼）是最常见的无人机平台形态。它能悬停、垂直起降、任意方向飞行——但也因此全方向运动都会产生姿态变化，对感知系统的动态范围要求极高。

⬆️

垂直起降（VTOL）

不需要跑道，室内外均可操作，适合精密任务。

🔄

全向机动

可以横滚、俯仰、偏航同时发生，导致感知坐标系快速旋转。

⚖️

有效载荷受限

通常1-10kg，传感器总重不宜超过10%起飞重量。

🔋

续航有限

通常20-60分钟，要求感知系统功耗 < 10-20W。

2.1.2 固定翼（Fixed-Wing）——远程续航之王

固定翼无人机需要跑道或弹射起飞，靠机翼产生升力，滑翔时能以极低功耗巡航数小时。它们适合测绘、巡检等需要长续航的任务，但无法悬停，对着陆点要求苛刻。

长续航：2-8小时（燃油型可达16小时+） 高速度：通常70-120km/h 大载荷：可达数十公斤 无法悬停：降落需要开阔场地或 parachute

2.1.3 垂直起降固定翼（VTOL）——两全其美

固定翼和多旋翼的结合——典型如DJI V-Tail或Autel EVO Max。既能像固定翼那样高效巡航，又能在需要时悬停。代价是结构更复杂、重量更大、价格更高。

2.2.1 传感器层：数据从哪里来？

飞控的传感器层通常包含一组惯性测量单元（IMU），这是飞控最核心的传感器——它以1kHz以上的频率采样，在GPS和视觉融合失效时提供姿态参考。

1

IMU（惯性测量单元）

以最高频率采样（1-8kHz），直接测量三轴加速度和三轴角速度。是姿态估计的最快数据源，也是所有融合算法的时间基准。

2

GPS / 双天线定向

提供绝对位置（NMEA格式）和航向角。更新率低（1-10Hz），但无累积误差。RTK版本可达到厘米级精度。

3

视觉 / 激光雷达

提供相对位移动估计（里程计），在GPS失效时（室内、峡谷）接管定位。通常通过USB/以太网接入飞控。

4

气压计 / 超声波 / ToF

提供高度参考。气压计测绝对高度（但有漂移），超声波/ToF测相对高度（精确但范围有限）。

2.2.2 感知层：传感器融合的核心战场

感知层是传感器融合算法运行的层次。它接收传感器层的原始数据，通过融合算法输出：机体六自由度姿态（位置+姿态）、速度（ENU系下）、周围环境地图（栅格或点云）以及障碍物位置。

关键约束：实时性

感知延迟是飞控的"生死线"

飞控的内环控制周期通常在100-1000Hz（1-10ms）。如果感知层的输出延迟超过50ms，姿态控制的稳定性会显著下降。这意味着：感知算法必须在有限时间内完成，算法复杂度必须与硬件算力匹配。很多"学术state-of-the-art"算法因为延迟过高而无法实际飞。

2.4 算力平台：从STM32到NVIDIA Jetson

传感器融合算法的算力需求差异巨大。选型需要在"算得够快"和"功耗够低"之间找到平衡。

2.4.1 微控制器层（MCU）

飞控核心芯片，通常是STM32H7或类似MCU，负责IMU数据读取、姿态控制（EKF）、电机控制。基本不运行感知融合算法，功耗< 1W。

2.4.2 单芯片计算机层（SBC）

独立计算模块，运行高级感知算法。常见选型：

🧡

2.5 总线架构与时间同步

传感器数据如何传到计算单元？不同总线技术在带宽、延迟和可靠性上有显著差异：

🔌

CAN Bus

高可靠性，实时性好，带宽有限（1Mbps）。飞控与电机ESC之间的标准协议。

🌐

Ethernet (100BASE-T)

千兆以太网：高速Lidar（如Ouster OS1-128/ Velodyne VLP-32C）的标准接口，带宽充足。

🖥️

MIPI CSI-2

摄像头专用接口，低功耗，高带宽。Jetson平台的标准摄像头接口。

⏱️

PTP / NTP / 硬件触发

时间同步协议。PTP（IEEE 1588）可实现亚微秒级同步，是多传感器时间对齐的标准。

2.5.1 时间同步的数学基础：时钟模型与同步误差

多传感器时间对齐的核心是理解时钟漂移模型。在分布式系统中，每个节点的本地时钟建模为：

🔑 时钟漂移的数学模型

设真实物理时间为 $\tau$，节点 $i$ 的本地时钟为 $C_i(\tau)$。本地时钟通常建模为：

$C_i(\tau) = a_i \cdot \tau + b_i + w_i(\tau)$

其中 $a_i$ 是时钟偏斜（clock skew，理想值为1），$b_i$ 是时钟偏移（clock offset），$w_i(\tau)$ 是随机游走噪声。

时钟偏斜的物理来源：晶振频率误差。MEMS IMU的晶振精度通常为 $\pm 50$ ppm，意味着每秒钟累计误差可达 $50\mu s$。对于需要微秒级同步的传感器融合系统，这个漂移不可忽视。

同步误差分解：
• 确定性误差（可校正）：时钟偏斜 $a_i$ 和偏移 $b_i$
• 随机性误差（不可完全消除）：晶振噪声、量化误差、通信延迟的不确定性

🔑 PTP（IEEE 1588）同步协议原理

PTP通过交换同步报文（Sync/Follow_Up/P_delay_Req/P_delay_Resp）测量路径延迟并校正时钟偏移。同步精度可达亚微秒级。

同步方程：
设主从时钟偏移为 $o$，路径延迟为 $d$。主时钟发送Sync报文（时间戳 $T_1$），从时钟接收时间 $T_2$：
$T_2 = T_1 + d + o$

从时钟发送Pdelay_Req（$T_3$），主时钟回复Pdelay_Resp（$T_4$）：
$T_4 = T_3 + d - o$

联立求解：
$o = \frac{(T_2 - T_1) - (T_4 - T_3)}{2}$
$d = \frac{(T_2 - T_1) + (T_4 - T_3)}{2}$

同步误差的主要来源：
① 非对称延迟：发送路径和接收路径的物理延迟不同。这是PTP的理论极限，即使时间戳精度无限高也无法消除。
② 时钟晶振噪声：同步后本地时钟仍会以 $50\mu s/s$ 量级的速度漂移，需要周期性重同步。
③ CPU调度延迟：软件时间戳的获取发生在操作系统调度之后，存在 $10-100\mu s$ 的不确定性。硬件时间戳（MAC层）可将此项降低到 $< 1\mu s$。

🔑 NTP时间同步协议

NTP（Network Time Protocol）是互联网时间同步的事实标准，通过多层时间服务器（stratum）分发UTC时间。NTP的同步精度：
• 局域网（同一子网）：$1-10ms$
• 广域网：$10-100ms$
• 互联网骨干：$< 10ms$

对于无人机飞控链路（要求 $< 1ms$ 同步），NTP精度不足，必须使用PTP或硬件触发同步。

2.5.2 实时调度理论基础

飞控系统是一个典型的实时系统——计算结果必须在严格的时间约束内产生，否则会导致系统失效。实时调度理论研究如何在有限计算资源下满足所有任务的时间约束。

🔑 实时任务模型与调度可行性

实时任务建模为三元组 $(C, T, D)$：
• $C$：最坏情况执行时间（WCET）
• $T$：任务周期
• $D$：相对截止期（通常 $D \leq T$）

利用率（Utilization）： $U = \sum_{i=1}^{n} \frac{C_i}{T_i}$

速率单调调度（RMS）可行性判定：
对于周期性实时任务，RMS是静态优先级调度最优策略。任务可调度的充分条件：
$\sum_{i=1}^{n} \frac{C_i}{T_i} \leq n \cdot (2^{1/n} - 1)$

当 $n \to \infty$ 时，右边趋近于 $\ln 2 \approx 0.693$。这意味着：
• 单任务：$U \leq 1$
• 双任务：$U \leq 0.828$
• 大量任务：$U \leq 0.693$

早期绑定与晚期绑定：
早期绑定将感知任务分配到固定CPU核心，减少调度开销但可能导致负载不均衡。晚期绑定动态分配，负载均衡好但调度开销大。飞控关键任务通常用早期绑定到专用核心。

🔑 多传感器数据流的调度优化

考虑一个典型的无人机感知数据流：
• IMU：$T_{imu} = 1ms$，$C_{imu} = 0.1ms$
• 相机：$T_{cam} = 33ms$，$C_{cam} = 5ms$
• Lidar：$T_{lidar} = 50ms$，$C_{lidar} = 10ms$

总利用率：$U = 0.1/1 + 5/33 + 10/50 = 0.1 + 0.152 + 0.2 = 0.452$

RMS可调度边界：$n=3$ 时为 $3 \times (2^{1/3}-1) \approx 1.089$（利用率小于1即可调度）

带宽预留（Bandwidth Reservation）：
为关键任务预留CPU带宽，非关键任务在空闲时间运行。Linux内核通过 cgroups 和 rt throttling 实现。

感知-控制链路的确定性保证：
对于飞控内环（$1kHz$，周期 $1ms$），必须保证每次都在 $1ms$ 内完成。使用 FIFO 调度 + 核心隔离（isolcpus）将控制任务固定在专用核心，消除调度不确定性。

第2章选择题

B. τ < 0.1/ω_c
C. τ < ω_c/π
D. 无约束要求

2. 无人机传感器总线的带宽选择与感知算法计算量的匹配问题，本质上是什么类型的优化问题？请从系统层面分析：假设传感器产生原始数据的速率为R_bps，通信总线带宽为B，感知算法处理延迟为τ，存储深度为D，则稳定性条件如何表达？
A. 实时调度问题：R_bps × τ ≤ B × T，其中T为调度周期
B. 缓存设计问题
C. 带宽越大越好，无约束
D. 延迟越小越好，无数学约束

3. 在嵌入式系统功耗预算分配中，飞控系统（STM32H7）通常预算< 1W，而高级感知系统（Jetson Orin）需要15-40W。请从系统架构角度分析：为什么感知系统不能简单地将功耗预算无限制地分配给高算力芯片？
A. 因为重量问题
B. 因为成本问题
C. 因为散热问题
D. 因为电池容量有限，功耗增加会直接缩短续航时间，续航与感知精度之间存在帕累托最优边界

A. 通信链路非对称性（发送和接收路径延迟不一致）
B. 晶振漂移累积
C. CPU调度延迟

5. 多传感器系统的时间同步架构设计中，假设IMU以1kHz采样（周期1ms），相机以30fps采样（周期33.3ms），Lidar以20Hz采样（周期50ms）。若采用软件时间戳方案，要求各传感器时间戳在统一时钟系下的对齐误差< 1ms，则对跨传感器数据缓冲机制（Buffer）的设计有什么数学要求？
A. Buffer深度需满足：最大采样周期差 × 数据速率 + 安全边际，且需使用双线性插值而非简单最近邻对齐
B. 任何Buffer设计均可满足要求
C. 不需要Buffer
D. Buffer越大越好

参考答案

答案：1.A 2.C 3.D 4.A 5.C

解析：

  1. 相位裕度要求90度时，感知延迟τ与姿态环带宽ω_c应满足τ < π/(2ω_c)，这是从频率域稳定性分析推导出的严格数学约束。
  2. 总线带宽与感知算法计算量的匹配本质上是实时调度问题：数据产生速率R_bps与总线带宽B以及处理延迟τ之间需满足R_bps × τ ≤ B × T的稳定性条件。
  3. 感知系统不能无限制分配功耗，因为电池容量有限，功耗增加直接缩短续航，感知精度与续航之间存在帕累托最优边界——这是嵌入式系统的根本约束。
  4. PTP通信链路非对称性是理论下限，因为发送和接收路径的物理延迟天然不同，即使时间戳精度无限高也无法消除这种结构性非对称。
  5. Buffer深度需容纳最大采样周期差（50ms - 1ms = 49ms）期间累积的数据，且插值应使用双线性插值以获得时间对齐的精确估计，而非最近邻丢弃。
