12.1 glTF 2.0：Web 3D的基石

12.1.1 glTF格式设计哲学

glTF（GL Transmission Format）被称为"3D领域的JPEG"，其设计目标是成为3D内容的高效传输和加载格式：

💡 glTF核心设计原则
1. 易于读取
   - JSON描述文件（.gltf）
   - 人类可读的节点层次结构
   - 二进制几何数据分离存储

2. 完整性
   - 场景图（Scene Graph）
   - 材质（PBR扩展）
   - 动画（关键帧/骨骼）
   - 皮肤（Skinnning）
   - 相机（Camera）

3. 高效传输
   - GLB（glTF Binary）打包所有数据
   - Draco压缩几何数据
   - KTX2压缩纹理

4. 格式层次
   glTF
   ├── .gltf（JSON + 外部bin + 外部texture）
   └── .glb（单一二进制文件，包含所有数据）

12.2 USD：Pixar的影视级场景描述

12.2.1 USD概述

USD（Universal Scene Description）是Pixar开发的场景描述格式，已成为影视和元宇宙领域的事实标准：

🎬

合成架构

LayerStack允许非破坏性合成

🔗

引用系统

AssetReference跨文件引用

💾

变体集

VariantSets多配置切换

⚡

高效加载

Crate二进制高效解析

12.2.2 USD核心概念

💡 USD关键概念
1. Prim（Primitive）
   - USD场景图的基本元素
   - 类似glTF的node，但更强大
   - 可携带Schema（物理属性、材质等）

2. Layer
   - USD文件的抽象
   - Session Layer → Root Layer（可堆叠）
   - SubLayers引用构成合成栈

3. VariantSet
   - Prim的可切换状态
   - 用于LOD、材质变体等
   - 运行时切换

4. Payload
   - 延迟加载大型资产
   - Reference外部.usd文件
   - Ar（Asset Resolution）系统解析路径

5. Strength（Override vs Prepend）
   - TimeCode：动画关键帧
   - Opinion：冲突解决

12.2.3 glTF vs USD

维度 glTF USD
设计目标 实时3D传输（Web/游戏） 影视特效合成
文件格式 JSON/binary ASCII（.usda）/binary（.usdc）
场景合成 单文件，无合成 LayerStack多层合成
变体系统 无内置 VariantSets
动画 关键帧+骨骼 TimeSampled属性
生态 Web/游戏为主 影视/Houdini/Unreal

12.3 WebGPU：新一代Web图形API

12.3.1 WebGPU vs WebGL

WebGPU是W3C正在标准化的新一代Web图形API，提供了更现代化的GPU编程模型：

🎮

计算着色器

WebGL完全不支持，WebGPU原生支持

📦

绑定模型

Descriptor Set（WebGPU）vs Texture Unit（WebGL）

⚡

Pipeline State Objects缓存编译

🔄

命令编码

GPUCommandBuffer显式提交

12.3.2 WebGPU核心概念

💡 WebGPU API层次
// 1. 适配器与设备
const adapter = await navigator.gpu.requestAdapter();
const device = await adapter.requestDevice();

// 2. 着色器模块（WGSL）
const shaderModule = device.createShaderModule({
  code: `
    @vertex fn vs(@location(0) pos: vec3f) -> @builtin(position) vec4f {
      return vec4f(pos, 1.0);
    }
    @fragment fn fs() -> @location(0) vec4f {
      return vec4f(0.0, 0.5, 1.0, 1.0);
    }
  `
});

// 3. 渲染流水线
const pipeline = device.createRenderPipeline({
  layout: 'auto',
  vertex: { module: shaderModule, entryPoint: 'vs' },
  fragment: { module: shaderModule, entryPoint: 'fs' },
  primitive: { topology: 'triangle-list' }
});

// 4. 绑定组（Descriptor Set等价物）
const bindGroup = device.createBindGroup({
  layout: pipeline.getBindGroupLayout(0),
  entries: [...]
});

// 5. 命令编码与提交
const commandEncoder = device.createCommandEncoder();
const passEncoder = commandEncoder.beginRenderPass({
  colorAttachments: [{
    view: textureView,
    loadOp: 'clear',
    storeOp: 'store'
  }]
});
passEncoder.setPipeline(pipeline);
passEncoder.draw(3);
passEncoder.end();
device.queue.submit([commandEncoder.finish()]);

12.4.2 Three.js集成

A-Frame基于Three.js构建，可直接访问Three.js API：

💻 A-Frame + Three.js自定义组件
// 注册自定义A-Frame组件
AFRAME.registerComponent('hover-glow', {
  schema: {
    color: {type: 'color', default: '#00ff00'},
    intensity: {type: 'number', default: 0.5}
  },

  init: function() {
    // 访问Three.js对象
    this.el.addEventListener('mouseenter', () => {
      this.el.setAttribute('material', 'emissive', this.data.color);
      this.el.setAttribute('material', 'emissiveIntensity', this.data.intensity);
    });

    this.el.addEventListener('mouseleave', () => {
      this.el.setAttribute('material', 'emissive', '#000');
      this.el.setAttribute('material', 'emissiveIntensity', 0);
    });
  }
});

第十二章选择题

1. glTF的GLB格式将所有资源打包为单一二进制文件。关于GLB的内部结构与Draco压缩的关系，以下分析正确的是？
A. GLB的JSON chunk可以直接被Draco压缩，不需要修改结构；压缩后的GLB仍然符合glTF 2.0规范　B. Draco压缩仅影响bufferViews中的几何数据（POSITION、NORMAL等），不会影响accessors和meshes的JSON描述　C. Draco解压后，顶点属性在GPU中的布局与原始glTF定义的accessor.byteStride保持一致　D. GLB+Draco组合在移动端WebGL 2.0下的解压性能显著优于桌面端，因为移动GPU有专用解码器

2. USD的LayerStack合成机制允许在不修改底层Layer的情况下覆盖属性。关于SessionLayer→RootLayer→SubLayers的优先级和override行为，以下分析错误的是？
A. Session Layer的优先级最高，可覆盖Root Layer和所有SubLayers的属性　B. SubLayers之间的相对顺序不影响最终合成结果，因为USD使用平等叠加而非堆栈　C. Payload提供延迟加载机制，但Payload本身也是Layer的一种形式，具有相同的override语义　D. VariantSet选择是Opinion强度的体现，stronger opinion可以覆盖weaker opinion，无论其来自哪一层

3. WebGPU的Pipeline State Objects（PSO）设计相比WebGL的即时编译模式，主要优势是？该设计对渲染性能的影响是？
A. PSO在创建时编译，运行时仅需绑定，避免了WebGL每帧编译的卡顿；但在切换流水线时仍有开销　B. PSO的编译是异步的，运行时绑定保证了100%的流畅度，不存在流水线切换开销　C. PSO缓存了所有着色器变体，解决了分支着色器在WebGPU中的性能问题　D. WebGPU的WGSL编译器比GLSL更高效，因此PSO编译比WebGL shader program链接快10倍

4. 在A-Frame中，组件是封装行为的基本单元。关于组件的lifecycle和Three.js对象的交互，以下分析正确的是？
A. init在组件首次挂载到实体时调用一次，update在每次schema属性变化时调用；两者都接收oldData参数　B. tick在每帧渲染前调用，其this.el指向对应的THREE.Object3D，而非a-element　C. 组件可通过this.el.getObject3D('mesh')访问关联的Three.js对象进行底层操作　D. 组件的remove回调在实体从DOM移除时不会被调用，因为浏览器不触发该事件

5. 在3D资产跨平台发布策略中，选择glTF+Draco还是USDZ格式的决策依据是？以下场景与格式匹配分析，正确的是？
A. iOS AR Quick Look要求USDZ格式，强制使用原因是SceneKit仅原生支持USD，glTF需要转换　B. Web端使用glTF+KTX2是因为KTX2的GPU解压比Basis Universal更快，且WebGPU原生支持KTX2　C. 游戏引擎（Unity/Unreal）内部使用USD是因为其更高效的合成架构，而非格式兼容　D. 当目标同时包含Web和iOS AR时，glTF+USDZ双格式发布比单一格式转换更高效

参考答案

答案：1.B　2.B　3.A　4.C　5.D

解析：

  1. Draco压缩的几何数据存储在bufferViews中，而accessors和meshes的JSON描述仅描述数据布局，不受压缩影响。
  2. SubLayers之间的相对顺序影响合成结果，后面的SubLayer优先级更高，会覆盖前面的属性。
  3. PSO在创建时预编译，避免了WebGL每帧编译的卡顿，但在切换流水线时仍有绑定开销。
  4. 组件通过this.el.getObject3D('mesh')访问Three.js对象，这是A-Frame与Three.js互操作的标准方式。
  5. 同时支持Web和iOS AR时，glTF+USDZ双格式是必要的，因为两者的要求不同，无法单一格式通用。
